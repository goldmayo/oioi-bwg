# P11 기존 관리자·사용자 화면 구조 개선

2026-11-01 사용자는 기존 화면 개선을 P11, 새 계정·권한·보안을 [P12](P12-PLAN.md)로
분리하고 문서화 및 P11의 작은 첫 작업을 지시했다. 이 문서는 여러 변경이 공유할 범위와
미정 사항을 소유한다. 현재 상태는 [WORK](../../../WORK.md), 단일 PR의 실행·검증은 PR 본문이 소유한다.

## 1. 기준과 관찰

[헌법](../../oioi-bwg-architecture-clean-v1/01-architecture-constitution.md),
[Frontend](../../oioi-bwg-architecture-clean-v1/02-frontend-architecture.md),
[Form/State](../../oioi-bwg-architecture-clean-v1/08-form-state-architecture.md),
[Testing](../../oioi-bwg-architecture-clean-v1/10-testing-architecture.md),
[Domain §8·15](../../DOMAIN_SPECIFICATION.md), [표현 기준](../../../PHILOSOPHY.md)을 따른다.

관찰 기준은 위 source의 `migration_main`이다. 초기 체크아웃은 오래된 feature 브랜치였으며
로컬 `migration_main`을 원격과 같은 SHA로 pull한 뒤 첫 작업 브랜치를 만들었다.
기존 미커밋 공개 웹 UI 제안·README 수정은 이번 변경에 포함하지 않는다. 운영 화면·DB를 재조회한 기록은 아니다.

- 곡·앨범 목록은 `packages/ui` Data Table을 사용한다. 열 조절·페이지 전체 선택 부품은 있지만
  Console 소비처는 정렬·페이지 이동만 등록했다.
- 곡 목록은 개별 선택·파형 작업 파일 다운로드와 검색/페이지 변경 후 선택 유지를 제공한다.
- 알림함은 단건 읽음·모두 읽음·이전 내역 조회·브라우저 push 설정을 제공한다. 현재 종류는 파형 성공/실패다.
- 공개 응원법은 재생·seek·강조·자동 스크롤·공연 모드 선택과 guide URL 연결을 제공한다.

## 2. 확정 범위와 미정 사항

| 영역         | 요청한 방향                                                                     | 구현 전 남은 결정                                            |
| ------------ | ------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 곡 추가·수정 | 넓은 편집 화면과 목록에서 1 depth                                               | 하위 페이지 또는 URL 연결 오버레이, 미저장 입력·목록 복귀    |
| 곡 열·필터   | YouTube ID, 공식, 사용자 노출, waveform, 콘서트, 페스티벌 표시 및 5개 상태 필터 | 아래 판정 단위, 같은 필터 내 다중 값 규칙                    |
| 선택         | 모두 선택 제공                                                                  | 현재 페이지/필터 결과 전체, 필터 변경 시 선택·일괄 작업 범위 |
| 알림 내역    | 테이블·필터                                                                     | 읽음/종류/기간 등 채택할 필터, 선택 읽음 필요성              |
| 공통 테이블  | 테이블 사용 화면에 열 너비 조절                                                 | 화면별 최소 너비·모바일 동작·설정 유지 범위                  |
| 공개 응원법  | 기존 동작을 보존하며 UI/UX 개선                                                 | 최신 화면에서 실제 불편 확인 후 범위 확정                    |

여러 필터의 동시 적용은 확정 요구다. 구체 연산은 제안과 확정을 구분하며 전체 구현 순서나 PR 분할을
아직 확정하지 않는다. YouTube ID 표시는 내부 UUID identity 변경이 아니다.

- 공식은 모드별 공개 snapshot의 `OFFICIAL/FANDOM` 출처다. 기존 관리자 `hasOfficialCheer`와
  공개 화면의 출처 판정이 다를 수 있으므로 새 필터의 권위로 legacy flag를 그대로 쓰지 않는다.
- 노출은 Song 설정, Album 설정, guide 공개 상태를 구분한다. 단일 열이 설정값인지 실제 노출인지 미정이다.
- 콘서트/페스티벌은 Song+mode별 guide다. 등록과 현재 공개를 구분하며 없음·비공개를 임의로 합치지 않는다.
- waveform은 데이터 존재와 현재 YouTube source에 맞는 유효 결과를 구분한다.
- 알림함을 여는 것만으로 읽음 처리하지 않는 기존 계약을 유지한다.

## 3. 첫 구현 단위: 곡·앨범 목록 열 너비 조절

승인된 오늘 범위는 기존 두 목록의 작은 확장이다. 공용 Data Table의 공식 sizing/resizing 기능과
기존 드래그·터치·좌우 방향키 부품을 활용한다. 도메인 API·권한·DB·P09 편집 도구는 변경하지 않는다.

첫 버전의 구현 선택:

- 열별 초기·최소 너비를 앱에서 지정하고 작은 화면은 테이블 영역 안에서 가로 스크롤한다.
- 기존 breakpoint별 숨김 열을 유지하되 숨긴 열을 전체 너비에 합산하지 않는다.
- 너비는 마운트된 목록의 표시 상태로만 유지한다. 새로고침/재진입 시 초기화하고 URL·계정·브라우저에 저장하지 않는다.
  장기 유지 방식은 후속 결정이며 이 선택을 전체 P11의 확정 정책으로 확대하지 않는다.
- 정렬·페이지 이동·곡 선택·편집/삭제 진입과 읽기 권한의 기존 동작을 보존한다.

검증은 저장소 기본 명령과 실제 소비 컴포넌트의 브라우저 fixture로 수행한다.
마우스·키보드·터치, 최소 너비, breakpoint 전환, 표 내부 스크롤과 문서 overflow를 확인한다.
fixture는 실제 DB·인증·운영 수용 검증과 구분하고 결과·화면 근거를 PR에 남긴다.

## 4. 경계와 완료 조건

P12의 초대·승인·재인증·감사는 이번 UI 확장에 섞지 않는다. 독립 설정 페이지의 필요성은 미정이다.
P09는 실제 사용 중 필요가 생길 때 개선하며 P10 Grid/Snap·BPM·타격 구간 선택을 가져오지 않는다.
공개 응원법 UX는 관리자 편집기 개선과 별도 관심사로 다룬다.

채택한 화면별 요구의 완료 조건과 검증을 합의하고, 구현·사용자 수용을 구분해 닫는다.
단일 열 조절 PR이 끝나도 P11 전체 완료로 판정하지 않는다. 여러 PR의 상세 기록을 이 문서에 복제하지 않는다.
P11 담당자는 범위 결정 때 이 계획을 갱신하고, 종료 시 유효 계약은 active 문서, 실행 요약은 단계 최종 결과로
회수한 뒤 이 계획의 유지·통합을 판단한다. 관련 없는 과거 문서 정리는 수행하지 않는다.
