# 폴더 분리에서 실행·캐시 소유권 분리까지

## 해결하려던 문제

모노레포가 되었지만 루트 의존성과 도구 설정이 앱 검사·캐시에 계속 결합돼 있었다.

## 진행과 결정

환경변수 입력과 검증, 설정의 자동 탐색 위치, 도구 workspace, 의존성 경계 분석, test 소속, task 입력과 앱별 Docker prune/build/cache를 정비했다.

## 시행착오와 회고

파일을 옮기는 것만으로 변경 영향이 줄지는 않았다. 직접 의존성과 실제 실행 주체를 확인하고 공통 변경의 affected 선택·cache invalidation을 함께 검증해야 했다.

## 검증과 한계

성과 수치는 결과 문서의 측정 조건을 따른다. 캐시 적중 검증과 최초 실행·전체 verify를 같은 성능 수치로 합치지 않는다.

이 글은 블로그 초안용 소급 기록이며 새 검증 결과나 당시 기록에 없는 동기를 만들어 넣지 않았다.
