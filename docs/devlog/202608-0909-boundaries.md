# API·상태·데이터 계층의 경계와 기반 검증

## 해결하려던 문제

기능이 늘면서 서버 row·HTTP·폼 초안·서버 캐시의 책임을 분리할 필요가 생겼다.

## 진행과 결정

RSC 직접 service 호출과 Client의 Query/ky/API 경로를 나누고 DTO·AppError·응답 검증·캐시 무효화를 명시했다. 이후 OTP 동시성·고유 제약·업로드 권한·PostgreSQL 검증을 보완했다.

## 시행착오와 회고

M7의 문서에는 PASS와 이후 FAIL 판정이 함께 남아 있다. 중간 PASS를 전체 도메인 전환 완료로 확대하지 않는다. 완료한 개별 수정과 재검토 결과를 각각 원문으로 추적한다.

## 검증과 한계

M7 후속 도메인 구현까지 완료했다고 기록하지 않는다. 결과의 로컬·mock·실제 PostgreSQL 검증은 원문에 적힌 범위를 따른다.

이 글은 블로그 초안용 소급 기록이며 새 검증 결과나 당시 기록에 없는 동기를 만들어 넣지 않았다.
